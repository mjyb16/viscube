# viscube — change report, week of 2026-06-29 → 2026-07-06

What changed in the package this week (v0.3.x → **v0.4.2**), why, and how it
was validated. Commits on `main` (pushed; verified 2026-07-06): `9e00b46`
"Adding deapodization code" → `04de3fe` "Adding code for final run" →
`94b0e0c` "Adding docs" → `0a37654` version → `2eb9c44` doc build fix.
Everything below was driven by the NGC 4697 2026-07-02 code review, which
confirmed that the legacy m=6 overlap gridding correlated neighbor-cell
noise and that the image-plane correction convention was inverted.

## 1. Non-overlapping m=1 Kaiser-Bessel gridder (the new default)

`grid_cube_all_stats_nonoverlap` (+ per-channel engine
`bin_channel_nonoverlap`). Algorithm: visibilities are assigned to UV cells
by `searchsorted` (one cell per visibility — the m=1 KB kernel support
coincides exactly with the bin), weighted within the bin by KB `m=1, β=2.0`
(β=0 reduces to a pillbox), and accumulated with `bincount`. Consequences:

- **No neighbor-cell noise correlation by construction.** Measured in
  `binning_scheme_tests.ipynb` (sknkwx): normalized-residual std ≈ 1.00 for
  all β; neighbor correlation ≈ 0 vs +0.32 for the legacy m=6 KDTree overlap.
- **~15–30× faster** than the KDTree path (bincount vs ball-tree queries).
- **Loud coverage accounting**: any visibility outside the grid raises a
  RuntimeWarning with count/percentage/worst channel + a printed summary.
  Pipeline notebooks assert 0% dropped. This closed the long-standing
  "silent max_uv truncation" TODO.
- **DC-cell Hermitian dedup** (`n_aug` bookkeeping): short baselines land in
  the u=v=0 cell where a visibility and its conjugate are the same cell —
  duplicates are removed (ID141: 49,500 removed, ~825/channel).

The KDTree gridders (`grid_cube_all_stats`, `_wbinned`) remain for
reproducing legacy products only.

## 2. Half-plane (Hermitian slab) storage

`half_plane_slab` / `half_plane_mask_fix`: for odd npix, keep slab rows
`[npix//2:]`; on the DC row, the left half is masked+zeroed (those cells are
conjugate-duplicates of the right half). This makes each independent complex
measurement appear exactly once — the fix for the Hermitian double counting
that inflated Fisher information ×2 in the legacy full-plane files (χ²/n at
the NGC 4697 old best fit dropped 2.09 → 1.05 purely from this).
Bookkeeping invariant used as a pipeline assert: occupied-cell count
full/half = 2.000 exactly (NGC low-res 102,438 → 51,219). The exact inverse
(`hermitian_full_from_slab`, implemented in the sknkwx viz notebooks:
`full[a,b] = conj(full[npix-1-a, npix-1-b])` + DC-row rebuild) is validated
to 2e-13 on the grid and 1e-19 on the dirty-image real part — required
before any dirty imaging of half-plane data. Storage cost: measured ×1.98
disk reduction (see `sknkwx .../viscube_compression/`).

## 3. Analytic de-apodization taper (`deapodization.py`, new module)

`make_kb_taper_1d` / `make_kb_taper_map`: the **analytic** Fourier transform
of the KB kernel (branch-safe sinh/sinc via `_kb_sinhc`), agreeing with the
numeric taper to ≤4e-5 where the numeric one is well-sampled — and required
at m=1, where numeric sampling of the kernel degenerates. Convention: the
forward model **multiplies** its image by this taper (matching m/β) before
the FFT; the gridded npz stores it as `taper_map`. The legacy convention
(dividing the model image by an un-truncated kernel map) was inverted and is
retained only as `stabilized_inverse_map` for reproducing old runs. Getting
this sign/convention right moved the NGC 4697 disk scale by +24% — it is not
a cosmetic fix.

## 5. Validation / regression status

No test suite in-repo. The de-facto validation lives in sknkwx:
`publication_run_nautilus/gridding/binning_scheme_tests.ipynb` (statistical
properties), the gridding notebooks' hard asserts (0% dropped, full/half
ratio 2.000, red/blue spectral order), and
`scripts/selfcheck_pipeline_fixes.py` (model↔data alignment at 1e-14,
taper-sign regression). Re-run those after touching `gridder.py`,
`grid_cube.py`, or `deapodization.py`. Reminder: the v-flip in
`uv_grid_to_fft_image_convention` remains load-bearing; outputs are
`(F, Nu, Nv)`.
